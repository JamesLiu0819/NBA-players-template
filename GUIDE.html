    1三條不能違反的規則

    1. 所有分析都是固定的算式。同樣的作答，永遠得到同樣的結果。不用 AI 判斷。
    2. 聯賽環境是算式的輸入。它直接乘進訓練優先度，不是算完之後再拿來修正。
    3. 網站執行時不向外部查資料。球員資料是事先做好的 JSON 檔。

    出處：CLAUDE.md「最重要的三條規則」。

    2五種檔案，各自只做一件事

    種類在哪裡只負責不可以做
    資料 JSONdata/存題目、球員、技能、原型、訓練菜單、環境倍率不放任何計算
    引擎 Pythonsrc/engine/所有算式：座標、距離、星等、原型、訓練計劃不讀檔、不連網、不用亂數、不看時間
    後端 Pythonserver/讀 JSON、呼叫引擎、把結果用 API 回給網頁；處理登入、存收藏和上次結果不自己重寫算式
    前端 HTMLsrc/ui/index.html畫面、按鍵、三種語言的文字、畫六角圖不做任何分析計算
    腳本 Pythonscripts/在自己電腦上手動執行：產生球員資料、校準門檻、模擬網站執行時不會跑（run_player_match.py 的兩個文字函數例外，後端有借用）

    三種語言怎麼切換

    • 資料有三份：data/zh/（繁中，預設）、data/zh-Hans/（簡中）、data/en/（英文）。
    • 三份的結構和數字必須完全一樣，只有文字不同。tests/engine/test_i18n_parity.py 會檢查。
    • 網頁呼叫 API 時帶 lang，後端就讀對應的資料夾。
    • 按鈕、標題這類介面文字不在 data/，而是在 index.html 的 UI_STRINGS。

    3一次作答的完整流程

    1. 前端 打開網站。index.html 呼叫 GET /api/form-data 拿題目，同時呼叫 POST /api/site-visit 讓瀏覽人次加 1。
    2. 前端 選球員池、回答 18 題。六軸定位 12 題（每軸 2 題，選 1 到 5）加身材 6 題（身高、體重必填）。沒登入的話，答案只存在瀏覽器的記憶體裡。
    3. 前端 按「查看我的球員模板」。把作答、球員池、語言一起送到 POST /api/template-results。
    4. 後端 檢查並讀資料。server/app.py 確認欄位齊全，讀該語言的題庫、技能、球員、原型、訓練菜單。
    5. 引擎 依序計算。六軸座標 → 身材百分位 → 跟每位球員的距離 → 取最近 10 位並給星等 → 原型 → 3 位深度模板 → 每位球員 × 4 種環境的訓練計劃。
    6. 後端 組成一包 JSON 回傳。10 位球員的 4 種環境計劃一次全部算好。有登入的話，同時把這次的 18 題原始作答存進資料庫，給「查看上次的結果」用。
    7. 前端 畫出「我的模板」和「訓練計劃」兩頁。切換環境或 10 位球員時不用再問後端，直接換顯示。只有搜尋 10 位以外的球員才會再呼叫後端。

    4算式

    每張卡片：算什麼 → 算式 → 例子 → 數字在哪裡改。六個軸是 A 持球創造、B1 外線投射、B2 禁區得分、C1 外圍防守、C2 禁區防守、D 運動表現。

    4.1六軸座標（每軸 0 到 100）

    每一軸有 2 題，各選 1 到 5 分。

    axis score = (average of the 2 answers − 1) ÷ 4 × 100
    例：A 軸兩題選 4 和 5 → 平均 4.5 → (4.5 − 1) ÷ 4 × 100 = 87.5。所以分數一定是 12.5 的倍數。

    算式在 src/engine/axis_position.py 的 score_axis_coordinates。題目在 data/zh/題庫.json。

    4.2身材先換成百分位

    為什麼：直接比公分，幾乎每個人都比所有 NBA 球員矮，永遠配到最矮的後衛。

    • 使用者：放到「一般打球的人」的常態分布上。身高平均 180、標準差 8；體重平均 78、標準差 12。超過 190 公分或 93 公斤後改用直線拉到 100。
    • 球員：看使用者自己的身材決定用哪一種算法。
    使用者的身高球員的百分位怎麼算
    185 公分以下看他在自己那個球員池裡排第幾
    195 公分以上跟使用者用同一條分布曲線
    185 到 195 之間兩種按比例混合
    w = (user height − 185) ÷ 10 (clamped to 0..1) player percentile = (1 − w) × rank in pool + w × population curve

    體重同樣的做法，分界是 88 和 98 公斤。臂展、摸高、100 公尺不換百分位，直接用 (value − min) ÷ (max − min) × 100。

    例：175 公分的使用者約在第 27 百分位，對到的是「在 NBA 裡排第 27 百分位」的球員，不是 NBA 最矮的那幾位。

    算式在 src/engine/body_fit.py 的 percentile_normalize_body。可以調的數字：GENERAL_POPULATION_BODY_STATS、HEIGHT_TRANSITION_LOW / HIGH、WEIGHT_TRANSITION_LOW / HIGH、TALL_ATHLETE_THRESHOLD_Z。

    4.3你跟一位球員的距離

    距離越小越像。用在 10 人對照表。

    distance = sqrt( diff(A)² + diff(B1)² + diff(B2)² + diff(C1)² + diff(C2)² + 1.5 × diff(D)² + sum of diff(each body field you filled in)² )
    • D 軸乘 1.5：運動能力的差距被看得比技術差距重。
    • 身材欄位：只算你有填、球員也有的欄位。

    算式在 src/engine/player_matching.py 的 rank_similar_players_by_style_and_body。D 軸權重是 D_AXIS_WEIGHT。

    4.4星等（相似度）

    把距離對照門檻表，距離小於等於哪一格，就拿那一格的星數。兩個球員池各有一張表。

    星數54.543.532.521.51
    現役（152 人）距離 ≤5256606367697378其餘
    歷史（72 人）距離 ≤6165717477818792其餘
    例：現役池、距離 64 → 超過 63、沒超過 67 → 3 顆星。
    • 星等只代表像不像，不代表球員強不強。
    • 第 1 名不到 2.5 顆星時，畫面會多一句「目前球員池裡沒有非常接近的對照組」。

    門檻在 src/engine/player_matching.py 的 CURRENT_POOL_STAR_THRESHOLDS、ALLTIME_POOL_STAR_THRESHOLDS。重新校準用 scripts/calibrate_star_thresholds.py。

    4.5球場定位原型（12 種）

    1. 拿 10 人對照表的前 5 名。
    2. 每位球員各自歸到最接近的原型：比六軸，再加上體型（他的身高、體重在球員池內的百分位平均）。
    3. 加權投票：第 1 名 5 票、第 2 名 4 票、第 3 名 3 票、第 4 名 2 票、第 5 名 1 票。
    4. 票數最高的原型勝出。平手時，取平手原型裡排名最前面那位球員的原型。

    畫面上的「一句話球探報告」就是該原型的 flavor 文字。

    算式在 src/engine/archetype.py 的 classify_archetype_by_majority。可以調：ARCHETYPE_MAJORITY_TOP_N（幾個人投票）、SIZE_AXIS_WEIGHT（體型多重要）。原型內容在 data/zh/原型.json。

    4.63 位深度模板

    模板怎麼挑
    技術模板只比 A、B1、B2、C1、C2 五個軸，距離最小的球員。不看 D 軸，也不看身材。
    身材模板只比身材欄位，距離最小的球員。
    天花板先留下「他贏你最多的那一軸是技術軸」的球員，再從中挑 D 軸跟你最接近的。意思是身體條件差不多、技術更成熟的人。找不到就顯示沒有符合的球員。

    算式在 src/engine/player_matching.py 的 find_skill_fit_template、find_body_fit_template、find_ceiling_template。

    4.7球員卡片上的成長建議

    1. 找出這位球員贏你最多的那一軸。
    2. 那一軸是 D → 固定顯示「身體天賦上有落差，不能單靠練習籃球技能」。
    3. 他的招牌技能剛好主要練那一軸 → 用招牌技能的驗收動作。
    4. 對不上 → 改用最能代表那一軸的技能。

    邏輯在 scripts/run_player_match.py 的 describe_growth_recommendation。句型是 GROWTH_ACTION_TEMPLATE、D_AXIS_GROWTH_TEMPLATE。

    4.8訓練計劃

    針對一位目標球員和一種聯賽環境，從 15 項技能裡挑出 1 到 5 項。

    第一步：每項技能算三個數字

    代號意思怎麼來
    G 差距你離目標球員多遠五個技術軸逐一算「球員 − 你」（負的當 0），乘上這項技能跟該軸的關聯度，再加總。D 軸不算。
    E 環境倍率這種聯賽裡這項技能多有用data/env_weights.json，0.5 到 2.0。選「無」時全部是 1.0。
    C 成本這項技能多難練data/zh/技能.json 的 cost_C，2 到 4。
    G = sum over A, B1, B2, C1, C2 of axis_relevance[axis] × max(0, player[axis] − user[axis]) P = G × E ÷ C
    例：外線投射跟 B1 的關聯度是 0.9。你的 B1 是 50、球員是 90，其他軸一樣 → G = 0.9 × 40 = 36。環境選「內縮防守 / 缺乏射手」E = 1.8，成本 C = 3 → P = 36 × 1.8 ÷ 3 = 21.6。

    第二步：決定列哪幾項

    1. 第 1 項一定是該球員的招牌技能，不管差距多少。畫面會標「招牌技能」。
    2. 其餘技能：G 大於 0 的才留，依 P 由高到低排。
    3. 其餘技能裡，P 不到最高那一項的 25% 就不列。
    4. 加上招牌技能，最多 5 項。所以計劃永遠不會是空的。

    第三步：決定每項的難度

    看你在該技能最主要那一軸的分數：

    你的分數難度
    低於 40entry 入門
    40 到 70advanced 進階
    高於 70mastery 精通

    第四步：查菜單。用「技能 + 難度」到 data/zh/訓練菜單.json 找對應的訓練項目（15 項技能 × 3 個難度 = 45 筆）。

    算式在 src/engine/skill_level.py（G）、src/engine/priority.py（P）、src/engine/training_plan.py（挑選和難度）。可以調：DIFFICULTY_ENTRY_BELOW、DIFFICULTY_MASTERY_ABOVE、TRAINING_PLAN_RELATIVE_THRESHOLD，以及 server/app.py 的 TRAINING_PLAN_TOP_N。

    4.9登入、上次結果、收藏、管理員

    全部是選擇性的：不登入也能用問卷、模板、訓練計劃。

    功能怎麼做
    登入只有 Google 帳號一種。用 Authlib 套件跟 Google 交換資料，登入狀態存在用 SECRET_KEY 簽章的 cookie 裡。Google 的設定或 SECRET_KEY 缺一個，登入功能就整個關閉、按鈕也不顯示。
    使用者用 Google 給的固定編號（google_sub）辨認，不用信箱，因為信箱可能會改。
    上次結果每次交卷新增一筆，只新增、不修改、不刪除。存的是 18 題原始作答，不是算好的結果；讀取時用現在的算式重算，所以算式改了，舊結果也會跟著更新。畫面只顯示最新一筆。
    收藏存「使用者 + 球員編號 + 球員池」，同一位球員不會存兩次。
    管理員登入信箱等於環境變數 ADMIN_EMAIL 才算。不是管理員的人呼叫那支 API 會拿到 404（假裝不存在），不是 403。

    登入和權限在 server/app.py；資料表 users、results、favorites 在 server/db.py 的 init_db 建立。設計理由見 docs/superpowers/specs/2026-10-21-google-login-accounts-design.md。

    • 沒登入的人重新整理頁面，作答和結果都會消失。只有語言和主題存在 localStorage。登入的人可以用「查看上次的結果」找回來。

    GET /api/form-data打開網站、切換語言18 題的題目文字和選項
    POST /api/template-results交卷、有結果時切換語言六軸座標、原型、球探報告、3 位深度模板、10 人對照表（每人含 4 種環境的訓練計劃）
    GET /api/players第一次在搜尋框打字該球員池全部球員的編號、名字、球隊
    POST /api/player-training-plan選了搜尋結果裡的球員該球員的座標和一份訓練計劃
    POST /api/feedback送出使用意見成功或失敗
    POST /api/site-visit打開網站加 1 之後的瀏覽人次
    GET /auth/login按「登入」轉到 Google 的登入畫面
    GET /auth/callbackGoogle 登入完成後自動轉回來記下登入狀態，回首頁。使用者在 Google 按取消也只是回首頁
    POST /auth/logout按「登出」清掉登入狀態
    GET /api/me打開網站目前登入的名字、信箱，以及登入功能有沒有開
    GET /api/my-results/latest登入後打開首頁上次交卷的完整結果（用現在的算式重算）。沒有就回 204
    GET / POST / DELETE /api/favorites載入收藏、按 ☆／★、在收藏頁移除收藏清單，或新增、移除的結果。要登入
    GET /api/admin/feedback管理員登入後所有使用意見。不是管理員就回 404
    GET / 和其他路徑瀏覽器載入頁面和圖片src/ui/ 裡的檔案。data/ 不會被公開。

    後端的三個固定動作

    1. 檢查輸入。缺欄位、語言或球員池不對、身高體重沒填 → 回 400 和錯誤訊息。
    2. 讀資料。依 lang 和 pool 讀 data/ 裡對應的 JSON。
    3. 呼叫引擎。自己不算任何東西，全部交給 src/engine/。

    安全設定：每個回應都帶三個安全標頭（禁止瀏覽器猜檔案類型、禁止被別的網站嵌入、不把完整網址外洩給其他網站）。登入 cookie 不能被頁面上的程式讀取、別的網站送來的請求不會帶上它，在 Render 上只走 HTTPS。設定在 server/app.py 的 add_security_headers 和 session_cookie_secure。

    7資料檔長什麼樣

    以繁中為例。簡中和英文是同樣的結構、不同的檔名。

    檔案筆數每一筆有什麼誰在用
    題庫.json12 + 6 題六軸題：屬於哪一軸、題目、5 句選項。身材題：欄位、單位、上下限、是否必填問卷畫面、座標計算
    球員.json152 人六軸座標、身材、特點、招牌技能配對、訓練計劃
    歷史球員.json72 人同上，球隊欄位改放代表年份選「歷史球員模板」時
    原型.json12 種名稱、六軸座標、體型、一句話球探報告原型分類
    技能.json15 項名稱、成本、跟六軸各自的關聯度、驗收標準訓練計劃
    訓練菜單.json45 筆屬於哪項技能、哪個難度、名稱、組數、次數、分鐘訓練計劃
    data/env_weights.json4 組每種聯賽環境對 15 項技能的倍率（不分語言）訓練計劃

    改資料時要記得

    • 球員資料不要手改。它是 scripts/build_players_seed.py 和 scripts/build_players_alltime_seed.py 產生的，要改就改腳本再重新產生。
    • 數字要三個語言一起改。只改一份，測試會失敗。
    • 簡中的資料可以用 scripts/build_zh_hans_data.py 從繁中轉出來。
    • 每個 JSON 最上面的 _description 和 _editable_fields 會說明哪些欄位可以改。

    8GitHub 與上線

    1. 本機 改完程式、跑過測試、commit。
    2. GitHub git push 到 main。遠端是 github.com/JamesLiu0819/NBA-players-template。
    3. Render Render 讀 repo 最外層的 render.yaml。裡面寫了怎麼安裝和啟動。接上 GitHub 之後，預設每次 push 都會自動重新部署。
    4. 啟動 安裝：pip install -r server/requirements.txt。啟動：gunicorn --chdir server app:app。
    5. 資料庫 資料庫在 Neon（免費版 Postgres），不在 Render。連線字串放在 Render 後台的環境變數 DATABASE_URL，server/db.py 用它存瀏覽人次、使用意見、使用者、上次結果、收藏。

    方案和費用

    • 網站：Render Starter 方案，每月 7 美元。不會閒置休眠，打開就有畫面。
    • 不用手動續費。Render 按秒計費，每個月初自動從帳號綁定的信用卡扣上個月的費用。卡片過期或刷不過才會出問題，到 Render 後台的 Billing 確認。
    • 資料庫：Neon 免費版。不會像 Render 的免費資料庫那樣到期被刪。
    • 資料庫連不上時網站照常運作，只是瀏覽人次不顯示、意見送不出去、登入相關功能失效。

    五個環境變數（都在 Render 後台的 Environment 設定）

    變數用途誰管理
    DATABASE_URLNeon 資料庫的連線字串手動，render.yaml 寫 sync: false
    SECRET_KEY替登入 cookie 簽章Render 自動產生
    GOOGLE_CLIENT_IDGoogle 登入手動，sync: false
    GOOGLE_CLIENT_SECRETGoogle 登入手動，sync: false
    ADMIN_EMAIL誰是管理員手動，sync: false

    sync: false 的意思：Render 只知道有這個變數，值由你在後台管理，push 新版本時不會被改掉。這些值絕對不要寫進 render.yaml，那份檔案會上傳到 GitHub。

    設定在 render.yaml。詳細步驟在 server/README.md。本機沒有 DATABASE_URL 時，資料只記在記憶體裡，關掉就不見。
