# 每日球員卡系統：交接文件

> 給另一個 AI 對話看的完整背景。讀完這份就能接手，不需要先前的對話紀錄。
> 整理日期：2026-11-06。網站擁有者用繁體中文溝通，回覆也請用繁體中文。

---

## 1. 這是什麼

「球探報告」是一個籃球球員分析網站（Flask 後端 + 單頁前端，部署在 Render，資料庫是 Neon Postgres，用 Google 登入）。使用者回答問卷，系統用**六軸座標**（A/B1/B2/C1/C2/D，各 0–100）找出最像他的 NBA 球員模板。

**每日球員卡**是準備加進網站的收集小遊戲：

- 登入的使用者**每天開一包**，一包 3 張球員卡
- 卡片分四個等級，**沒有「命定」卡**（不能指定想要的球員）
- 重點是開包過程要**刺激、有多巴胺**：選包、撕包、一張張翻卡、稀有卡特效
- 卡片內容直接用網站的球員庫（六軸、原型、招牌技能），跟主功能有關聯

**目前狀態：只有試玩版（prototype），還沒做進正式網站。**

## 3. 專案的硬性規則（CLAUDE.md）

1. **分析不用 AI**：所有計算都是確定性的純函數，同樣輸入永遠同樣輸出。
2. **執行期不連外部 API**：資料離線建好、存成靜態檔。
   ⚠️ 試玩版的照片是直接連 Wikimedia 的。正式版必須在建庫時**下載照片存到網站自己的資料夾**。
3. `src/engine/` 只放純函數，不能有 I/O、亂數、時間依賴，每個函數都要有單元測試。
4. 程式碼與 commit 用英文；介面文字用繁體中文。
5. 網站有繁中、簡中、英文三語版本，三份資料結構必須完全對應（有測試把關）。
6. 新增檔案要登記到 `GUIDE.html` 的檔案清單（CI 會跑 `scripts/check_guide.py` 檢查）。

## 4. 抽卡規則

### 等級與機率（每張卡各自抽一次等級）

| 等級 | 每張機率 | 張數 | 怎麼決定 |
|---|---|---|---|
| 傳奇 | 3% | 15 | 網站擁有者手選：Jordan、LeBron、Kareem、Magic、Bird、Kobe、Duncan、Shaq、Curry、Wilt、Russell、Hakeem、Jokic、Durant、Giannis |
| 史詩 | 12% | 34 | 依生涯成就手動分級：MVP、多次年度第一隊、75 大核心球星 |
| 稀有 | 30% | 61 | 依生涯成就手動分級：名人堂、年度最佳防守、現役多次全明星 |
| 普通 | 55% | 99 | 其餘 |

- **不會重複**：已經擁有的卡不會再抽到，同一包裡也不會重複。
- **某個等級收齊後**，它的機率按比例分給剩下的等級。
- 用「六軸總分」或「單季獎項」自動排名，名單都不好（例如 Embiid 拿過 MVP 卻落在普通），所以四個等級都改成手動依生涯成就分（2026-11-06）。

### 保底

- **連續登入保底**：連續登入的每第 7 天，那包的第 3 張至少是史詩。
- **傳奇保底**：連續 14 天沒開到傳奇，第 14 天的第 3 張保證是傳奇。
- 模擬結果：第一張傳奇中位數大約在第 8 天出現；全部收齊大約 71 天。

### 確定性

- 一包的內容 = `rng(fnv(使用者代號 + "|" + 第幾天 + "|" + 第幾包))`，其中 rng 是 mulberry32。
- 同一個人同一天重新整理，看到的三包內容都一樣。
- 一包裡的三張排序是**最弱的在前、最好的放最後**，越翻越期待。
- 每天以**台灣時間午夜**換日。

### 試玩版特有的東西（正式版不會有）

- 狀態存在瀏覽器的 localStorage（key：`card-pack-prototype:2026-11-01`）。
- 「試玩用控制」區塊有四個按鈕：跳到下一天、下一包保證出傳奇、清空收藏重來、看全部卡片。

## 5. 開包流程（使用者看到的順序）

1. **選卡包**：畫面上有三個卡包，一包在前、兩包在後，地板上有倒影，像旋轉木馬。左右滑動換一包，點前面那包就選定。
   - **三包外觀完全一樣**：封面剪影只是裝飾，不暗示裡面有什麼。
   - 滑鼠移上去沒有任何提示，不會透露等級。
2. **撕開**：上方出現「沿著綠線往右滑開」，按住卡包沿綠色撕線往右拖。
   - 撕的過程中封口跟著手指裂開、有光從開口透出來、有撕紙聲和震動，快撕完時卡包會抖。
   - 放手沒撕完會彈回去。
   - 另有「不想滑？直接撕開」按鈕，Enter 鍵也可以撕。
3. **卡片堆**：三張卡疊成一堆，先側著飛進來露出厚度，再轉正。後面的卡只露出一點邊。
4. **翻卡**：點卡片翻開。翻的時候卡片往前抬起再轉，不會穿過後面的卡。
   - 點第二下，或往旁邊滑，這張卡就移走。移走時保持正面朝上。
   - 卡片上方出現粉紅色 NEW 標籤（第一次拿到的卡）。
   - 卡片下方出現稀有度：◆ 普通、◆◆ 稀有、◆◆◆ 史詩、金色 ★ 傳奇。
   - 右下角有圓形「按住快轉」按鈕，按住就一直自動翻。
5. **稀有卡特效**
   - 稀有：藍色光暈、小彩紙。
   - 史詩：紫色光暈脈動、彩紙、畫面震動、手機震動。
   - 傳奇：畫面變暗、金色放射光、卡片放大、大量彩紙、和弦音效，卡面有一條緩慢掃過的彩虹折射光。
6. **結算**：三張卡排成一列，顯示「今天收下 3 張新卡」、下一包倒數、收集進度、「看收藏冊」按鈕。
7. **收藏冊**：依等級分頁，已收集的卡顯示照片，沒收集的是虛線鎖住的格子。
8. **機率公開**表格放在頁面下方。

音效全部用 WebAudio 即時合成，不需要音效檔。手機震動用 `navigator.vibrate`。系統開了「減少動態效果」時，動畫會關掉。

## 6. 視覺設計

整體參考 **Pokémon TCG Pocket** 的開包流程，卡面參考 **Topps Now** 實體球員卡。

### 頁面
- **深色背景**（#0e1118），上面疊一層很淡的木地板紋路。
- 主字體用 Big Shoulders Display（標題、數字）和 Noto Sans TC（中文）。

### 卡包
- 圓角大、偏立體：有側邊厚度、中間鼓起的柔光、邊緣反光、地板陰影。
- 上方是**低彩度灰藍色**的封口條，有淡淡的六角格紋，上面放 logo、「球探報告」和紅色「DAILY CARD PACK」標籤。
- 綠色撕線。
- 封面是一個白色球員剪影，配上單色漸層背景：
  - 藍色包：灌籃剪影（CC0）
  - 綠色包、紅色包：網站擁有者提供的兩張運球剪影
- 下方是斜體白字「DAILY PACK」。
- **不要**加的東西：「第幾天・幾張」、右上角的 S1 標記、彩色線條、白色斑點。

### 卡片
- **偏直角**的小圓角（9px）、有厚度（看得到白色卡紙邊）、銀色斜面外框。比例 200×297。
- **卡面**由上到下：
  - 左上角 logo、右上角等級標籤
  - 照片填滿整個畫面；六軸雷達縮成左下的圓形小徽章
  - 右下是斜切的面板，裡面放圓形隊徽：現役球員放球隊縮寫，歷史球員放代表年份
  - 斜切的深色名牌，放大寫斜體英文名，名字太長會自動縮小字級
  - 白色副標條：原型・招牌技能（・歷史）
  - 最下面是一條深色的照片出處（攝影者・授權・Wikimedia Commons，授權規定要寫）
- **卡背**：深藍素底、一圈細金線內框、中間放 logo 和字距拉開的「球 探 報 告」。**每張卡背都一樣**，翻開前看不出等級。不要加格子花紋。
- 沒有照片的球員，卡面改用大的六軸雷達圖。

### Logo（已定案 A1d）
- 一個六角形外框，裡面是一塊**菱形鑽石狀**的籃球皮：橘色加黑色球縫。
- 雷達六軸的值是 `[0.98, 0.72, 0.72, 0.98, 0.72, 0.72]`（順序：上、右上、右下、下、左下、左上）。
- 正式網站的導覽列和瀏覽器分頁圖示已經換成這個 logo（本機 commit，尚未推上線）。

## 7. 卡片資料格式

試玩版 `DATA.players` 裡每張卡的欄位：

```json
{
  "id": "jrue_holiday",
  "n": "Jrue Holiday",
  "t": "POR",
  "pool": "c",
  "c": {"A": 87.5, "B1": 87.5, "B2": 25.0, "C1": 87.5, "C2": 12.5, "D": 12.5},
  "a": "防守大鎖",
  "s": "換防跟防",
  "tier": "common",
  "no": 126,
  "ph": {"u": "https://upload.wikimedia.org/...jpg", "a": "攝影者", "l": "CC BY-SA 4.0"}
}
```

| 欄位 | 內容 |
|---|---|
| `t` | 現役球員放球隊縮寫；歷史球員放代表年份 |
| `pool` | `c` 現役、`h` 歷史 |
| `c` | 六軸座標，直接來自球員庫 |
| `a` | 原型。有手動指定的 `archetype_id` 就用它，否則用 `engine.archetype.classify_archetype(座標, 原型清單, 體型)` 算，體型用 `compute_player_sizes(同一個球員池)` |
| `s` | 招牌技能，`signature_skill_id` 對應到 `data/zh/技能.json` 的中文名 |
| `no` | 卡號 1–209，傳奇在最前面 |
| `ph` | 照片網址、攝影者、授權。沒有照片的球員沒有這個欄位 |

## 8. 球員照片

### 來源與授權
- 照片全部來自 **Wikimedia Commons**，只用免費授權：CC BY、CC BY-SA、公有領域、CC0。卡面上一定要標註攝影者和授權。
- **NBA 官方照、Getty 照片不能用**（版權問題）。
- 網站擁有者確認球員卡**不會用來賺錢**。這點很重要：一旦有營利，用真實球員肖像做收集卡就需要球員工會授權。

### 選照片的規則（網站擁有者定的）
1. **最重要：看得清楚球員的臉。**
2. 有比賽動作（上籃、投籃、運球）是**加分**，不是必要條件。
3. 最好穿所屬球隊的球衣。
4. 臉不能被右上角的等級標籤擋住。

### 現況（209 張）
- 大約 125 張是看得清楚臉的比賽照。
- 大約 85 張用維基百科條目的主照片，原因有兩種：找不到更好的免費比賽照，或比賽照太遠、只拍到背影。
- 部分傳奇球員的照片是退休後拍的（例如 Magic、Kareem），但臉清楚。
- 新秀和年輕球員常常只有大學時期的照片，例如 Ty Jerome、Yaxel Lendeborg、Banchero。
- **Trey Murphy III** 沒有任何免費授權的照片，卡面維持雷達圖。

### 已知的坑
- Commons 上同一張照片的說明常常同時寫了兩個球員的名字，自動搜尋很容易配錯人（曾經配錯 7 位）。**換照片後一定要用眼睛確認是本人。**
- Wikimedia 有流量限制，一次載入太多縮圖會被擋。

## 9. 做進正式網站還需要做的事

1. **engine 純函數**：把 `drawPack`（含機率、不重複、保底）搬到 `src/engine/`，寫單元測試。種子 = 使用者 id + 台灣時間的日期 + 第幾包。
2. **資料庫**（Neon Postgres）：新增資料表，記錄每位使用者擁有的卡、每天開過的包、連續登入天數、距離上次開到傳奇幾天。
3. **API**：取得今天的三包（要登入）、開包（伺服器端檢查今天開過沒有、寫入結果）、取得收藏冊。**結果以伺服器為準**，前端只負責演出。
4. **照片離線化**：寫一支 `scripts/` 腳本，在建庫時把照片下載到網站資料夾，並把攝影者和授權存進資料檔。執行期不連 Wikimedia。
5. **卡片資料**：把等級、卡號、照片資訊做成資料檔（三語結構一致），不要再內嵌在 HTML。
6. **前端頁面**：導覽列新增「球員卡」頁，沿用試玩版的動畫與樣式，拿掉試玩用控制。
7. 把新檔案登記到 `GUIDE.html`，更新 CLAUDE.md 的目錄說明。

## 11. 跟網站擁有者合作的方式

- 用**繁體中文**回覆，句子簡短具體，多用條列、粗體和表格（網站擁有者有 ADHD）。
- 檢討或審查的結果：每個問題用一句話講完。
- 優化類的小改動可以直接做；功能、規則、設計方向這類重大決定，先整理成 HTML 提案頁讓他看。
- 改完畫面要截圖確認，再回報。
